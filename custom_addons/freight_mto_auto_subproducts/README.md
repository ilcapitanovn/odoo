# Freight MTO Auto PO Sub-Products (Odoo 15)

## Install
1. Copy `freight_mto_auto_subproducts` into your addons path.
2. Apps > Update Apps List > install "Freight MTO Auto PO Sub-Products".

## Use
Product > Purchase tab > "MTO Auto PO Sub-Products": add lines
(Sub-Product, Vendor override, Default Qty, Notes, Active, drag to reorder).

When a "Buy" procurement (MTO from a confirmed SO) creates a PO line for the
product, one line per active sub-product is added:
- qty = Default Qty x main line qty (converted to the product's own UoM);
  sub-product UoM = its purchase UoM
- price = vendor pricelist of the sub-product for the PO vendor (0 if none)
- no vendor override (or same vendor as the PO) -> same PO
- different vendor -> separate draft PO for that vendor (same origin,
  flagged "Auto Sub-Products PO"); reused if one already exists
- if Odoo merges extra demand into an existing main line, the sub-lines are
  increased by the matching amount
- generated lines are flagged (`is_mto_auto_line`, `mto_parent_line_id`) and
  stay fully editable. Later SO/PO edits do not re-sync.

## Assumptions to verify against freight_mgmt
- MTO purchases go through `stock.rule._run_buy` (Replenish on Order + Buy).
  Service-to-purchase (`sale_purchase`) is not covered.
- Product A stays on the PO as its own line.
- Reordering-rule (orderpoint) replenishments are not expanded.
- Nested sub-products are blocked.

## Suggest Sub-Products (v15.0.1.3.0)
Product > Purchase tab > "Suggest Sub-Products" (Purchase / Stock managers).
Popup with a "Suggest by" radio (default: name / vendor similarity) and a Reload
button to rebuild the list after changing the option. Tick the lines to add, edit
vendor / qty, then "Add Selected". The 20-line maximum counts lines already in the
grid (system parameter `freight_mto_auto_subproducts.suggest_max`). Already-present,
archived, non-purchasable and "main" products are skipped.

### 1. Product name and vendor name similarity (default)
- Keywords default to the words of the main product name minus the ignored words;
  editable. Every purchasable product is searched (accent-insensitive, partial
  words: `JJ` finds `SJJ`) in its own name AND in the names of its vendors.
- Score = matched keywords / keywords matching at least one product, +25% when the
  product is bought from a "favoured vendor" (defaults to the main product's
  vendors). Ticked by default when >= 2 keywords match or the vendor is favoured.
- Ignored words: list kept in Purchase > Configuration > Sub-Product Ignore Words
  (also editable as tags in the popup; added words are saved globally, removing a
  tag only applies to the current search). Every word of an entry is ignored; an
  entry of several words (e.g. "Entrusted Export Service") also hides products whose
  name contains the whole phrase, so other main products are not suggested.
- Vendor column: the product's vendor, empty when it is the main product's vendor.

### 2. Purchase history
- A booking = a source document (SO number) in the PO origin. Products on confirmed
  POs sharing the origin of past POs of this product (any vendor), ranked by the
  number of bookings. Ticked when seen in >= 50% of bookings. Qty = average per unit
  of the main product; vendor = most frequent (empty if same as the main PO vendor).
  Lines generated by this module are ignored. No fallback when there is no history.
